# neukarustihS

手机优先的本地音乐播放器。午夜蓝、酸柠绿，和属于自己的音乐收藏。

[打开播放器](https://meltingblue3.github.io/neukarustihS/)

## 使用

1. 在音乐库点击右上角「导入音乐」，选择文件夹或多选歌曲。文件夹会递归读取，有多个文件夹时逐个添加即可。重复导入会重新连接已有歌曲，不增加重复条目。
2. 点击歌曲播放；底部迷你播放器可展开封面、进度和歌词。
3. 歌曲的「更多操作」可以收藏、加入队列、管理歌单和导入 LRC。
4. 在 Android Chrome 菜单选择「安装应用」或「添加到主屏幕」。也可以使用设置页的安装按钮；从主屏幕以独立应用打开时，设置里不再展示安装入口。
5. 设置页显示当前版本，并提供「检查更新」。新版本就绪后点击「更新并重新打开」，不会在播放期间自动刷新。

支持常见 MP3、FLAC、M4A、AAC、WAV、OGG/Opus 等文件的元数据读取；实际播放格式取决于浏览器解码能力。支持内嵌封面、歌曲/艺术家/专辑搜索、排序、收藏、歌单、队列调整、随机、单曲/列表循环、睡眠定时和系统媒体控制。

播放器左侧的同一个模式按钮依次切换「列表循环 → 单曲循环 → 随机播放」。初次使用默认列表循环；选中的模式保存在本机，刷新、重新打开、切歌或应用更新不会重置，直到再次手动切换。旧版本的循环和随机偏好会迁移到对应模式。

文件夹导入时，同名 LRC 只匹配同一目录下的歌曲，避免不同专辑之间串词。单独多选文件时按文件名匹配，也可以在播放器歌词页单独导入。点击歌词可跳转；支持多时间戳和 offset。

文件夹选择能力取决于设备和浏览器：优先使用可保存文件句柄的目录选择器，否则使用浏览器文件夹上传入口。若设备选择器不支持目录，可改用多选音乐文件。读取失败的文件或子文件夹会跳过并提示。

### 中文翻译与振り仮名

把 `歌曲名.lyrics.json` 与同名歌曲、LRC 一起导入，也可以在歌曲已有的情况下补充导入，或从歌词页「更换歌词」为当前歌曲指定文件。文件夹导入只匹配同目录歌曲；单独导入遇到多个同名歌曲时会提示，请从对应歌曲的歌词页导入。

增强文件包含完整时间轴和原文，因此不必同时提供 LRC。播放器收藏爱心旁的「注音」「译文」可分别开关，偏好保存在本机，离线也能显示。增强文件优先显示；更换为内容不同的 LRC/TXT 会移除该歌曲的增强显示，重新导入相同 LRC 则保留。

UTF-8 JSON 格式如下（版本 1，最大 2 MB）：

```json
{
  "format": "neukarustihs-lyrics",
  "version": 1,
  "lines": [
    {
      "timeMs": 1200,
      "text": "夜の歌",
      "translation": "夜晚的歌",
      "segments": [
        { "text": "夜", "reading": "よる" },
        { "text": "の" },
        { "text": "歌", "reading": "うた" }
      ]
    }
  ]
}
```

`timeMs` 是从歌曲开始计算的非负整数毫秒；每行 `segments` 的文字拼接必须与 `text` 完全一致，包括空格和标点。没有译文时使用空字符串；间奏使用空 `text`、空 `translation` 和空 `segments`。文件内容仅作文本显示，不执行 HTML。播放器不联网生成翻译或注音，需要提前准备文件。

## 本地数据与离线

- 音频仅从用户选择的本地文件播放，不上传服务器、不复制到浏览器存储。
- IndexedDB 保存歌曲信息、封面、歌词和可用的文件句柄；localStorage 保存歌单、收藏和偏好。
- 重新打开后，浏览器可能要求重新选择原来的文件。重新选择会连接已有条目，保留收藏和歌单。支持文件访问 API 的浏览器会尝试恢复授权。
- 第一次联网访问后，Service Worker 缓存完整应用及解析器。之后可以断网打开、选择本机文件和播放。
- 浏览器清除网站数据、隐私模式结束、存储回收等操作可能移除记录。不同浏览器、设备之间不自动同步。
- 仅移除音乐库条目，不会删除原始文件。后台播放、锁屏控制和文件访问支持受设备、浏览器及系统省电影响。
- 原创插画随应用提供，不包含任何第三方歌曲。

## 开发

Node.js 22.12+（建议 24），npm。

```sh
npm ci
npm run dev
```

开发地址：`http://localhost:5173/neukarustihS/`。

```sh
npm run build
npx playwright install chromium
npm test
```

测试使用生成的短 WAV 音频，验证实际播放、歌词跳转、收藏和歌单、重连、队列、自动切歌、移动布局与离线导入。测试音频和截图不会提交。

## 发布 GitHub Pages

仓库的 Pages 源设置为 `gh-pages` 分支根目录。确认 GitHub Git 凭据已经配置：

```sh
npm run deploy
```

命令先执行类型检查和生产构建，再把 `dist` 推送到 `gh-pages`。源代码维护在 `main` 分支。页面更新通过应用设置里的更新按钮应用，避免播放过程中自动刷新。

更换仓库名时，需要同步修改 `vite.config.ts` 中的 `base`、manifest 的 `id`、`scope` 与 `start_url`。

## 版本管理

源代码与每次迭代提交保存在 GitHub 的 `main` 分支，GitHub Pages 的构建产物维护在 `gh-pages`。`v1.0.0` 标记最初的稳定基线；后续版本使用 Git 标签和 [CHANGELOG.md](CHANGELOG.md) 记录，可以定位并恢复指定发布。应用内版本号由 `package.json` 在构建时注入。

应用图标的源文件是 `public/favicon.svg`，修改后运行 `npm run icons` 生成普通与 Android 自适应安装图标。

## 代码结构

- `src/App.tsx`：音乐库、播放器、歌单、设置和手机界面。
- `src/store.ts`：持久化、文件导入、音频生命周期与媒体控制。
- `src/lib.ts`：文件标识、时间格式、LRC 解析和队列边界。
- `src/lyrics.ts`：翻译、注音增强文件的格式与校验。
- `src/pwa.ts`、`vite.config.ts`：安装清单、缓存和可控更新。
- `tests/player.spec.ts`：浏览器端播放及离线回归。

React + TypeScript + Vite；Zustand；IndexedDB / idb-keyval；music-metadata；vite-plugin-pwa；Lucide。
